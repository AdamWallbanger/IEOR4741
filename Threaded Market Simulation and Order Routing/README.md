Architecture:
The system follows a three-thread pipeline architecture that models a simplified trading workflow. The MarketDataFeed thread continuously generates simulated price updates and pushes them into a shared priceQueue, notifying the next stage through a condition variable. The StrategyEngine thread consumes these updates, compares each new price to the previous one, and if the change exceeds a defined threshold, creates a corresponding buy or sell Order. These orders are passed into an orderQueue for the OrderRouter, which logs each order to a CSV file and measures latency. This design cleanly separates data generation, strategy logic, and output handling while maintaining thread safety through mutexes and condition variables.
Threading strategy
The program uses multithreading to divide its workload into three concurrent tasks that communicate through synchronized queues. Each thread has a distinct responsibility: the MarketDataFeed thread produces continuous price updates, the StrategyEngine thread analyzes those updates to decide when to trade, and the OrderRouter thread records the resulting orders. By running these components in parallel, the system mimics a real trading pipeline where data generation, decision-making, and order logging occur simultaneously. Thread safety is maintained through mutexes and condition variables, ensuring that data is passed correctly between threads without race conditions or unnecessary busy-waiting.
Analysis of bottlenecks and trade-offs
The main bottlenecks in this system arise from synchronization and file I/O. Each queue operation requires acquiring a mutex and waking threads through condition variables, which introduces latency and limits scalability as message rates increase. In addition, the per-order CSV writes performed by the OrderRouter thread create an I/O bottleneck, especially at higher feed rates. Reducing synchronization frequency or batching log writes would improve throughput but slightly delay data visibility. Thus, the design balances simplicity and real-time responsiveness against peak performance—prioritizing correctness and clarity over raw speed.
